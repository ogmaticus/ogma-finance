# Финансы — сервер v2

Собственный сервер вместо ChatGPT Sites: Node.js 22 + PostgreSQL 16, данные хранятся в России (Selectel).
Внешних npm-зависимостей у сервера нет: используются только встроенные модули Node.js.

## Что внутри

| Файл | Назначение |
|---|---|
| `main.mjs` | Точка входа: настройки из окружения, миграции, запуск |
| `app.mjs` | HTTP: маршруты, cookie-сессии, раздача приложения, заголовки безопасности (CSP, nosniff, frame-ancestors) |
| `auth.mjs` | Вход по коду на почту, сессии, журнал согласий, ограничение частоты, удаление аккаунта |
| `pg.mjs` | Клиент PostgreSQL (протокол v3, SCRAM-SHA-256, пул, транзакции) |
| `db.mjs` | Миграции и адаптер, повторяющий интерфейс Cloudflare D1 |
| `file-store.mjs` | Хранилище скриншотов на диске с шифрованием AES-256-GCM |
| `mail.mjs` | Отправка писем: smtp (рабочий режим), file (тесты), console (отладка) |
| `pages/` | Страницы входа, политики и согласия |
| `migrations/` | SQL-миграции (применяются при старте) |
| `../server/budget.ts` | Логика бюджета, копий и файлов — та же, что в версии 1.9.x |

## API

Совместимо с клиентом 1.9.x, плюс новые маршруты:

- `POST /api/auth/request-code` — `{ email }`, отправляет 6-значный код (10 минут, не чаще 1 в минуту и 5 в час на адрес, 20 в час на IP).
- `POST /api/auth/verify` — `{ email, code, consent }`, создаёт сессию (cookie `fin_session`, HttpOnly, SameSite=Lax, Secure на HTTPS, 30 дней). Новому пользователю нужно `consent` = текущая версия согласия. После 5 неверных попыток код аннулируется.
- `GET|POST /logout` — завершает сессию.
- `DELETE /api/account` — удаляет бюджет, копии, скриншоты, сессии и пользователя; запись согласия обезличивается и помечается отозванной.
- `GET /api/session`, `/api/budget`, `/api/backups`, `/api/files`, `/api/files/:id` — как раньше.

Все изменяющие запросы требуют заголовок `Origin`, совпадающий с `PUBLIC_ORIGIN` (защита от CSRF).

## Локальный запуск

```sh
cp .env.example .env    # заполните DATABASE_URL и секреты
set -a; . ./.env; set +a
npm run server
```

Секреты: `openssl rand -hex 32` для `APP_SECRET` и `FILES_KEY`.

## Тесты

```sh
# пустая тестовая база
TEST_DATABASE_URL=postgres://finance:pass@127.0.0.1:5432/finance_test npm run test:server
npm test   # тесты клиента
```

## Развёртывание на сервере

1. Ubuntu 24.04, в `/root/.ssh/authorized_keys` — ключ доступа.
2. Скопировать проект в `/opt/finance`.
3. `bash /opt/finance/deploy/setup.sh` — тестовый режим по IP (HTTP);
   `bash /opt/finance/deploy/setup.sh finance.example.ru` — с доменом и HTTPS.

Скрипт ставит Node.js 22, PostgreSQL, Caddy, создаёт пользователя `finance`, базу, файл секретов
`/etc/finance/finance.env`, службу systemd с ограничениями, межсетевой экран (22/80/443),
автообновления безопасности, ежедневный дамп базы (`/var/backups/finance`, 14 дней) и отключает вход по паролю.

**Ключ `FILES_KEY` нужно сохранить отдельно:** без него зашифрованные скриншоты не восстановить.

Журнал: `journalctl -u finance -f`. В режиме `MAIL_TRANSPORT=console` коды входа видны в журнале — только для тестов.

## Ограничения текущей версии

- Бюджет по-прежнему хранится одним документом (предел 1,9 МБ, как в 1.9.12). Следующий шаг — операции отдельными строками.
- Вход через Яндекс ID / VK ID ещё не подключён.
- Резервные копии пока лежат на том же сервере; перенос в S3 Selectel — до публичного запуска.
- Тексты политики и согласия — черновики для проверки юристом.
