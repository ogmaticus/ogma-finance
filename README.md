# Финансы — бюджет и импорт банковских скриншотов

Публичный интерфейс: `public/app.html`; скрипты работают без клиентской сборки. Серверные маршруты Vinext находятся в `app/api`, логика хранения — в `server/budget.ts`. Корень сайта переходит на `/app.html`.

## Данные

Гостевой бюджет остаётся в старом ключе `finance-prototype-v1`. После входа через ChatGPT бюджет хранится в D1 по доверенному идентификатору посетителя. В браузере есть отдельная копия для каждого пользователя. Старые данные переносятся по явной команде; исходный гостевой бюджет сохраняется.

Каждое серверное сохранение сверяет номер версии. Снимок создаётся раз в 30 минут или перед импортом, слиянием и восстановлением. Хранятся 30 последних снимков и по одному за последние 12 месяцев. При слиянии учитываются даты изменения и удаления; удалённые записи не возвращаются со старого устройства.

Новые импортированные скриншоты сохраняются сначала в IndexedDB, затем в R2 после входа. Файлы доступны только владельцу. Изображения, не сохранённые предыдущими версиями приложения, восстановить невозможно. JSON-экспорт содержит только бюджет. Полная ZIP-копия содержит бюджет и оригиналы всех доступных скриншотов, включая изображения из архива без активных операций. Перед скачиванием приложение сообщает об отсутствующих исходниках.

Схема JSON и ZIP допускает до 4 МиБ после миграции; отдельный скриншот — до 10 МБ (PNG, JPEG, WebP). При выгрузке копии проходят все страницы архива. Суммы в schemaVersion 3 хранятся целыми копейками (`amountMinor`, `openingMinor`, `targetMinor`, `savedMinor`, лимиты). Schema 1/2 и старые ZIP мигрируют автоматически. `public/budget-schema.js` проверяет серверные записи, восстановление и локальное чтение, ограничивает поля и отбрасывает неизвестные. На устройстве сохраняется отдельная исходная копия старого бюджета до миграции; её можно скачать в личном кабинете. Она удаляется при выходе вместе с остальными данными владельца.

## Установка и работа без сети

`manifest.webmanifest`, значки и `sw.js` позволяют установить веб-приложение на главный экран. При установке скачивается только оболочка. OCR-ресурсы кешируются отдельно при первом импорте или по кнопке «Подготовить распознавание без интернета». Без сети распознавание доступно после сохранения этих ресурсов. Версии оболочки, OCR-кеша и URL модулей генерируются из `release.json` скриптом `scripts/generate-release.mjs` перед сборкой. При выходе удаляются бюджет и скриншоты аккаунта с устройства; гостевой бюджет сохраняется.

При возвращении сети проверяется текущий аккаунт. Изменения для другого пользователя сохраняются в его локальной копии и не отправляются в новый аккаунт. Сервер также сравнивает ожидаемого владельца с доверенной сессией. API, авторизация и серверные оригиналы скриншотов не попадают в кэш сервисного работника.

Новый сервисный работник ждёт команды обновления. Интерфейс запрещает перезагрузку во время импорта, открытого редактирования и сохранения. Перед обновлением сохраняется локальная копия бюджета. При активации сохраняется предыдущая оболочка для другой ещё открытой вкладки. Данные в localStorage, IndexedDB, D1 и R2 не удаляются при обновлении оболочки.

Установку на физических Android/iPhone и полный пользовательский вход необходимо проверить на устройствах. Очистка данных браузера удаляет несинхронизированные локальные изменения.

## Проверки и сборка

- `node scripts/test-finance.mjs` — даты и дневные итоги, сопоставление карты, типы операций, категории, повторное нажатие импорта и сохранение исходников после ошибки.
- `node scripts/test-backups.mjs` — перенос бюджета и оригиналов, новые ссылки другого аккаунта, повреждения, конфликт версий, ошибки хранилища и выгрузка более 100 файлов.
- `node scripts/test-cloud.mjs` — настоящие изолированные D1/R2: доступ владельцев, конкурирующие сохранения, копии, изображения; клиент: перенос старого бюджета и сохранение конфликтов.
- `node scripts/test-pwa.mjs` — состав офлайн-кэша, отсутствие приватных маршрутов, защита черновиков при обновлении.
- `npx tsc --noEmit` — типы сервера.
- `npm run build` — сборка Vinext.

`.openai/hosting.json` сохраняет идентификатор существующего сайта и привязки `DB`, `BUCKET`. SQL в `drizzle/` применяется платформой при публикации. Применённые миграции нельзя переписывать; для новых схем генерируются новые миграции через `npm run db:generate`.

Вход и выход обслуживает платформа. `app/chatgpt-auth.ts` доверяет заголовкам `oai-authenticated-user-*`. Это безопасно **только на ChatGPT Sites**, где их устанавливает доверенная инфраструктура. На другом хостинге необходимо заменить этот механизм проверяемой авторизацией (сессией/OAuth); нельзя просто доверять входящему id, иначе посетитель сможет подставить чужой идентификатор. Самостоятельная регистрация и нативные мобильные приложения пока не реализованы.

## Код и проверки

Клиент — ES-модули без сборщика. `public/state.js` содержит общее состояние, `public/events.js` делегирует события через `data-action`. В HTML нет встроенного JavaScript. `server/app-shell.ts` выдаёт HTML по `/app` и `/app.html` с CSP, `nosniff` и Referrer-Policy; wasm и локальный worker OCR разрешены.

```sh
npm ci
npm test
npm run lint
npm run format:check
npm run build
```

`npm test` запускает все регрессионные тесты и `tsc`. Playwright: `npm run test:e2e` (требуется установленный Chromium); конфигурация содержит 390×844 и 1440×900. Сценарии используют тестовые данные и перехватывают API авторизации. `.github/workflows/test.yml` готов к запуску в GitHub; само наличие файла не означает, что CI был запущен на репозитории Sites. SQL используется непосредственно; новые миграции добавляются в `drizzle/`, применённые файлы не переписываются.

Если IndexedDB не принял исходники, приложение удерживает их в памяти и показывает повторное сохранение; обновление в этот момент запрещено. Закрытие страницы до успешного сохранения может потерять эти несохранённые изображения. Полная копия переносит сами изображения и восстанавливает их связи с операциями. До замены бюджета сохраняется предыдущий; файлы прежнего бюджета не удаляются.

Для ошибочно прочитанного знака валюты есть повторное распознавание отдельного символа: только у числовой строки в колонке сумм с геометрически отделённым последним символом. Последняя цифра обычной суммы не отбрасывается. Полные проходы OCR запрашивают только текст и блоки, без неиспользуемых HTML/TSV-выгрузок.

## Формат полной резервной копии

ZIP с записями без дополнительного сжатия содержит `manifest.json`, `budget.json` и `screenshots/<SHA-256>.png|jpg|webp`. Поддерживается до 10 000 оригиналов и размер ZIP до 4 ГБ. Скриншоты уже сжаты в своих форматах; архив собирается из Blob-частей, CRC проверяется блоками, весь ZIP не распаковывается в один массив памяти. Каждый исходник ограничен 10 МБ. Чтение принимает только профиль архивов, создаваемых приложением; самостоятельно пересжатый или зашифрованный ZIP не поддерживается.

Проверяются CRC32, SHA-256, структура бюджета, типы изображений, состав файлов, уникальность имён и связи. После проверки пользователь подтверждает замену. Для аккаунта изображения сначала отправляются в собственное хранилище, затем бюджет сохраняется по номеру версии; конфликт не меняет текущий бюджет. При ошибке могут остаться уже сохранённые дополнительные исходники, но прежние операции и файлы не удаляются. Гостевое восстановление сохраняет оригиналы в IndexedDB и позволяет открыть их из операции. Перенос гостевого бюджета после входа также переносит восстановленные архивные изображения.

В процессе экспорта и восстановления автоматическое обновление, сохранение и смена контекста при reconnect приостанавливаются. Для полной копии аккаунта нужен интернет. Пользователь подтвердил скачивание ZIP на Android. Подтверждение восстановления, ход работы и итог показываются в одном анимированном окне; ошибки остаются видимыми до закрытия. Пользователь подтвердил восстановление ZIP на Android после исправления окна. Safari ещё требует проверки.

## Бюджеты по месяцам

`budgetsByMonth` содержит полные планы категорий для месяцев `YYYY-MM`. При отсутствии записи используется прежний `limits`; первое изменение создаёт отдельный план выбранного месяца, сохраняя старый объект. Пустой месячный план означает отсутствие лимитов и не возвращает прежние значения. Ноль — допустимый лимит без расходов. Копирование прошлого месяца заменяет только план выбранного месяца.

Расходы и возвраты считаются в копейках за выбранный месяц. Возврат уменьшает расходы своей категории; поступления и внутренние переводы не расходуют лимиты. Остаток по плану учитывает только категории с лимитами, расходы без лимитов показаны отдельно. Предупреждение появляется с 80%, превышение отмечено отдельно. Из бюджета история категории открывается за текущий выбранный месяц.

Месячные планы проходят валидацию API и резервных копий; при переносе гостевого бюджета сохраняются разные месяцы, а план локального месяца заменяет серверный целиком, включая убранные лимиты. Схема D1 не меняется. `node scripts/test-monthly-budget.mjs` проверяет расчёты, переход года, перенос, ZIP, сохранение в интерфейсе и смену аккаунта. Отображение нового раздела на реальном телефоне ещё не проверено.

Выбор месяца использует кнопки предыдущего/следующего месяца и собственное анимированное окно с месяцем и годом; стандартное поле браузера `type=month` заменено. Выбор хранится отдельно в `finance-view-month`, не меняет финансовые данные и восстанавливается после обновления. У истории категории отдельный фильтр месяца с теми же элементами управления. Проверены переход декабря/января, выбор даты, границы года, некорректные значения, сохранение фильтра и отсутствие записи бюджета при переключении. Новые элементы на реальном телефоне ещё требуют проверки.

В разделе «Категории» на карточках расходов есть отдельная кнопка «Задать лимит» / «Изменить лимит» для месяца, выбранного в шапке. В истории категории есть блок лимита с явным месяцем: используется месяц истории, а при «Все даты» — месяц в шапке приложения. Сохранение лимита обновляет карточки и оставляет открытой обновлённую историю. Для доходной категории «Зарплата» без расходов и для внутренних переводов лимит расходов не предлагается. Проверены открытие формы, отмена, сохранение в нужный месяц и обновление истории.

## План хранения после 1.9.12

Текущий предел одного канонического бюджета — 1 900 000 байт UTF-8, общий для клиента и сервера (D1 ограничивает строку 2 000 000 байт). С 80% интерфейс предлагает скачать копию. Существующие локальные документы большего размера остаются читаемыми и экспортируемыми; новые записи и восстановление сверх предела отклоняются без замены сохранённых данных.

Следующий этап: хранить операции отдельными строками с owner/id, индексами даты/счёта/категории, пагинацией и версионированием. Перенос выполнять новой миграцией с проверкой количества операций и контрольных сумм, резервной копией и возможностью отката. До этой миграции автоматический перенос в архив не выполняется.
