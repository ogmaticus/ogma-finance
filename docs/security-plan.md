# План безопасности «Финансов» (сервер v2)

Зафиксировано 16.10.2026 перед первым развёртыванием на Selectel.
Выполняем поэтапно после запуска сервера. Отмечаем `[x]` по мере выполнения.

## Что уже сделано

- Вход по одноразовому коду на почту: 6 цифр, 10 минут, 5 попыток; в базе хранится HMAC кода, сравнение за постоянное время.
- Ограничения частоты: 1 запрос в минуту и 5 в час на почту, 20 в час на IP.
- Сессия `fin_session`: HttpOnly, SameSite=Lax, Secure на https, 30 дней; в базе — sha256 идентификатора.
- Проверка Origin (CSRF), строгая CSP, `frame-ancestors 'none'`, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Скриншоты на сервере зашифрованы AES-256-GCM; загрузка в облако только по явному включению.
- Сервер: вход по SSH только по ключу, ufw (SSH, 80, 443), unattended-upgrades, служба systemd с усиленной изоляцией.
- Серверная часть без npm-зависимостей.
- Удаление аккаунта, журнал согласий, данные хранятся в РФ.

- [ ] **Домен и HTTPS.** A-запись на IP сервера, переменная `DEPLOY_DOMAIN`, развёртывание с полной настройкой; Caddy получает сертификат Let's Encrypt. Без HTTPS приложением пользуется только разработчик.
- [x] **SMTP для писем с кодом** (16.10.2026): Яндекс, пароль приложения, настройки из секретов GitHub `SMTP_USER`/`SMTP_PASSWORD`. Осталось: отдельный ящик на домене (Яндекс 360) вместо личного. Подключить почтовый сервис, указать `SMTP_*` и `MAIL_FROM` в `/etc/finance/finance.env`, настроить SPF/DKIM/DMARC для домена.
- [x] **Защита GitHub** (17.10.2026): 2FA, правило `protect-main` (запрет удаления и force push). Обязательные проверки — при переходе на pull request. Двухфакторная аутентификация на аккаунте; правило для ветки `main`: без force push и удаления, обязательные проверки «Finance checks».
- [x] **Замена ключа развёртывания** (17.10.2026): новый ключ `github-deploy-2` создан на компьютере владельца, закрытая часть только в секрете GitHub и у владельца; старый отозван (`deploy/deploy-keys-revoked`). Текущий закрытый ключ передавался через чат. Сгенерировать новую пару у себя, публичную часть добавить на сервер, закрытую — в секрет `DEPLOY_SSH_KEY`, старый ключ удалить из `authorized_keys`.
- [ ] **Копия `FILES_KEY` и секретов** из `/etc/finance/finance.env` — в менеджер паролей. Без `FILES_KEY` скриншоты не расшифровать.

Сервисный пользователь `finance-backup-writer` (роль s3.user в проекте); политика бакета: ему разрешена только загрузка (PutObject), чтение/список/удаление запрещены (проверено: 403), владельцу — полный доступ.
