# План безопасности «Финансов» (сервер v2)

Зафиксировано 16.10.2026 перед первым развёртыванием на Selectel.
Выполняем поэтапно после запуска сервера. Отмечаем `[x]` по мере выполнения.

## Что уже сделано

- Вход по одноразовому коду на почту: 6 цифр, 10 минут, 5 попыток; в базе хранится HMAC кода, сравнение за постоянное время.
- Ограничения частоты: 1 запрос в минуту и 5 в час на почту, 20 в час на IP.
- Сессия `fin_session`: HttpOnly, SameSite=Lax, Secure на https, 30 дней; в базе — sha256 идентификатора.
- Проверка Origin (CSRF), строгая CSP, `frame-ancestors 'none'`, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Скриншоты на сервере зашифрованы AES-256-GCM; загрузка в облако только по явному включению.
- Сервер: вход по SSH только по ключу, ufw (SSH, 80, 443), unattended-upgrades, служба systemd с усиленной изоляцией.
- Серверная часть без npm-зависимостей.
- Удаление аккаунта, журнал согласий, данные хранятся в РФ.

## Этап 1 — до первых сторонних пользователей

- [ ] **Домен и HTTPS.** A-запись на IP сервера, переменная `DEPLOY_DOMAIN`, развёртывание с полной настройкой; Caddy получает сертификат Let's Encrypt. Без HTTPS приложением пользуется только разработчик.
- [ ] **SMTP для писем с кодом.** Сейчас `MAIL_TRANSPORT=console` — коды пишутся в журнал сервера. Подключить почтовый сервис, указать `SMTP_*` и `MAIL_FROM` в `/etc/finance/finance.env`, настроить SPF/DKIM/DMARC для домена.
- [ ] **Защита GitHub.** Двухфакторная аутентификация на аккаунте; правило для ветки `main`: без force push и удаления, обязательные проверки «Finance checks».
- [ ] **Замена ключа развёртывания.** Текущий закрытый ключ передавался через чат. Сгенерировать новую пару у себя, публичную часть добавить на сервер, закрытую — в секрет `DEPLOY_SSH_KEY`, старый ключ удалить из `authorized_keys`.
- [ ] **Копия `FILES_KEY` и секретов** из `/etc/finance/finance.env` — в менеджер паролей. Без `FILES_KEY` скриншоты не расшифровать.

## Этап 2 — сразу после запуска

- [ ] **Бэкапы вне сервера.** Ежедневный `pg_dump` и каталог файлов шифровать (age или gpg) и отправлять в отдельное хранилище (Selectel S3) с отдельным ключом доступа только на запись; хранить 14–30 дней. Раз в месяц проверять восстановление.
- [ ] **Мониторинг.** Внешняя проверка `/healthz` с уведомлением (Telegram или почта); оповещения о всплесках неудачных входов и ошибок 5xx.
- [ ] **Отдельный пользователь для развёртывания** вместо root: права только на `/opt/finance` и перезапуск службы через ограниченный sudo; `PermitRootLogin no`.
- [ ] **Окружение `production` в GitHub** с ручным подтверждением развёртывания; закрепить действия GitHub Actions по SHA.
- [ ] **Журналы:** не писать почту и IP в открытом виде дольше необходимого; ротация журналов.

## Этап 3 — к публичному запуску

- [ ] **Шифрование бюджетов.** Сейчас данные бюджета в базе хранятся открыто (зашифрованы только скриншоты). Решить: шифрование на стороне сервера с ключом вне базы или сквозное шифрование (усложняет синхронизацию и восстановление).
- [ ] **Шифрование диска / тома** с базой, если доступно у Selectel.
- [ ] **Управление сессиями:** список устройств, «выйти везде», уведомление о входе с нового устройства.
- [ ] **Независимая проверка на уязвимости** (пентест) и разбор результатов.
- [ ] **Документы 152-ФЗ:** проверка политики и согласия юристом (сейчас черновики с `[ФИО]`, `[ИНН]`), уведомление в Роскомнадзор, письменное подтверждение от Selectel о размещении данных в РФ.
- [ ] **План реагирования на инциденты:** кто и как отключает сервис, отзывает сессии, меняет ключи, уведомляет пользователей и РКН (обязанность при утечке ПДн).
