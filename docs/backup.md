# Резервные копии «Финансов»

## Как устроено

Каждую ночь (около 03:30 по времени сервера) служба `finance-backup` делает:

1. **Дамп базы** `pg_dump` → `/var/backups/finance/db-<время>.dump`. Локально хранится 14 дней.
2. **Проверку восстановлением**: дамп разворачивается во временную базу `finance_restore_check`, количество строк в ключевых таблицах сверяется с рабочей базой, временная база удаляется.
3. **Внешнюю копию** (если есть `/etc/finance/backup.env`): архив из дампа и каталога `files/` (скриншоты, уже зашифрованные `FILES_KEY`) шифруется **открытым** ключом [age](https://age-encryption.org) и загружается в S3 Selectel (другой провайдер, данные в РФ).

Закрытого ключа age на сервере нет. Взлом сервера не даёт прочитать старые копии; ключ S3 у сервера — только на запись, удалить или подменить копии с сервера нельзя.

При любой ошибке systemd запускает `finance-alert@finance-backup.service` — письмо на `ALERT_EMAIL` с последними строками журнала. Так же оповещает о падении самого приложения (`finance.service`).

## Что нужно для внешней копии (один раз)

1. **Selectel → S3:** создать приватный бакет (например `ogma-finance-backups`, стандартный класс), правило жизненного цикла «удалять объекты старше 30 дней».
2. **Сервисный пользователь S3** с правом только на запись в этот бакет → ключ доступа (Access key + Secret key).
3. **Ключ age:** `age-keygen -o finance-backup.key`. Строка `# public key: age1...` — открытый ключ; сам файл — **закрытый ключ, хранить в менеджере паролей, на сервер не класть**.
4. На сервере: `cp /etc/finance/backup.env.example /etc/finance/backup.env`, заполнить, `chmod 600`. В `/etc/finance/finance.env` указать `ALERT_EMAIL` (и SMTP).
5. Проверка: `systemctl start finance-backup && journalctl -u finance-backup -n 20`.

## Восстановление

1. Скачать нужный `finance-<время>.tar.age` из бакета (панель Selectel → объект → скачать) на сервер.
2. Положить закрытый ключ во временный файл, например `/root/restore.key` (права 600).
3. Пробный прогон (ничего не меняет): `finance-restore finance-....tar.age /root/restore.key`
4. Восстановление: `finance-restore finance-....tar.age /root/restore.key --yes` — останавливает приложение, заменяет базу и файлы, запускает приложение.
5. Удалить ключ: `shred -u /root/restore.key`.

Для расшифровки скриншотов нужен тот же `FILES_KEY`, что был на сервере: при переезде на новый сервер перенесите `/etc/finance/finance.env` (копия — в менеджере паролей).

## Учебное восстановление

Раз в квартал: скачать свежую копию и выполнить шаг 3 (пробный прогон). Копия, из которой ни разу не восстанавливались, не считается копией.
