# Этап 2 — качество кода и безопасность

Редизайн этапа 3 не начат. Клиентская версия — v1.9.3 (релиз оболочки 22); пакет переименован в `finance-app`, версия пакета `1.7.0` согласно заданию.

## Изменения

1. Prettier подключён; форматирование сделано отдельно в коммите `1bf2f4a2c6c4c941632a3423630027332baee3f4` без изменения логики приложения. ESLint проверяет клиент и сервер.
2. Клиент переведён на ES-модули с явными импортами. `state.js` содержит общее изменяемое состояние. `events.js` использует делегирование, HTML не содержит inline-обработчиков.
3. Добавлены CSP с поддержкой wasm/local worker, `X-Content-Type-Options: nosniff` и `Referrer-Policy: same-origin` для страницы приложения. На опубликованном хостинге заголовки выдаются Worker-маршрутом `/finance`, потому что файл `_headers` в проверке не применился. Прежний адрес `/app.html` содержит переход на `/finance`; PWA кеширует полную защищённую страницу `/finance`.
4. Старые установленные оболочки получают совместимое представление через API до применения обновления. Суммы и лимиты хранятся целыми копейками в schemaVersion 3. Миграция поддерживает прежние бюджеты и ZIP. Форматирование больших значений и сумм меньше рубля выполняется без потери последней копейки. Переполнение точного диапазона отклоняется.
5. Общая схема ограничивает поля и типы, очищает неизвестные поля; используется сервером, локальным чтением и восстановлением. Для старых данных на устройстве сохраняется исходная копия до миграции, доступная для скачивания. При выходе она очищается вместе с данными владельца.
6. Размеры JSON и multipart ограничены при потоковом чтении без зависимости от Content-Length. Неожиданные ошибки получают анонимный requestId, метод, маршрут и очищенное сообщение; email и SQL-значения не записываются.
7. Удалены неиспользуемые UI-компоненты, hooks, examples, connector-код, Drizzle-схема и индекс, корневые модели OCR и лишние зависимости. React/Vinext и инфраструктура Sites сохранены для серверной сборки. Применённые SQL-миграции не изменены.
8. OCR не входит в установочный кеш. Модели кешируются при первом использовании или подготовке без сети. Версии URL/SW генерируются из одного `release.json`.
9. Новая операция получает сегодняшнюю дату в текущем месяце, иначе последний день выбранного месяца. Последние операции сортируются по дате и времени. Новые sourceId — SHA-256 содержимого; старые связи по имени/размеру/mtime остаются совместимыми. Даты демонстрационного бюджета зависят от текущего месяца.
10. Добавлены `npm test`, CI-конфигурация, Playwright-сценарии для двух размеров экрана и предупреждение о переносе авторизации с Sites.

## Проверки и их пределы

Прошли `npm test` (включая TypeScript), ESLint, проверка форматирования и сборка. Регрессии охватывают прежние функции, миграцию сумм, ZIP schema 1, точные копейки, ограничения полей, остановку потока без Content-Length, новые даты, сортировку, SHA-256, кеш OCR и связывание настоящего графа ES-модулей. Удаление и синхронизация проверяются в изолированных D1/R2, без удаления реальных пользовательских данных.

Playwright зарегистрировал 8 сценариев: ручная операция, демо-импорт, лимит и выход — каждый для мобильного и настольного размера. **Браузерные e2e здесь не выполнены; CI-файл добавлен, но запуск GitHub CI не подтверждён.** Реальные OCR/wasm под CSP на Android и Safari требуют ручного прогона. Структура модулей, пути ресурсов, разрешения CSP и политика кеша проверены программно; это не заменяет проверку распознавания в браузере.

1. Применить обновление, убедиться, что прежние счета, цели, операции и лимиты сохранились.
2. Создать расходы 0,10 ₽ и 0,20 ₽: общий расход 0,30 ₽; изменить/удалить одну запись. Проверить начальный остаток и пополнение цели.
3. Проверить дату новой операции в текущем и прошедшем месяце; последнюю операцию с более ранней датой добавления.
4. Распознать реальный скриншот банка при наличии сети. Проверить даты, переводы, категории и карту по последним четырём цифрам.

6. Скачать ZIP, восстановить прежнюю копию версии 1.6 на тестовом аккаунте, проверить суммы и исходные изображения.
