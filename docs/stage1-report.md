# Этап 1 — сохранность и управление данными, клиент v1.8

Выполнены пункты 1.1–1.4 задания `prompt-finance-v1.7.md`. Этапы 2 и 3 не начаты.

## Что изменено

- Счета, операции, цели и правила категорий получили `updatedAt`; цели и правила — стабильные ID. Старый формат автоматически преобразуется при чтении. Удаление помечается `deletedAt`; удалённые записи исключены из расчётов, списков и выгрузки. При слиянии выбирается более позднее изменение, при равном времени — локальное. Лимиты, планы по месяцам и привязки карт имеют отдельные метки изменения и удаления.
- Полная удалённая запись очищается спустя 90 дней. Компактная отметка удаления остаётся, чтобы старое устройство не вернуло запись после очистки. Явное восстановление из копии может вернуть операции.
- Выход с несохранёнными изменениями или неотправленными изображениями предлагает синхронизацию, скачивание копии или выход без сохранения. Неудачная синхронизация блокирует выход. При выходе удаляются кеш, отметка переноса, копия до восстановления и изображения текущего пользователя. Данные других аккаунтов и гостевой бюджет сохраняются. Офлайн-доступ хранит данные до выхода; это указано в интерфейсе.
- Автосохранение — через 2,5 секунды и при скрытии страницы. Серверный снимок создаётся раз в 30 минут либо перед импортом, слиянием и восстановлением. Хранятся 30 последних снимков и по одному за каждый из последних 12 месяцев; очистка выполняется в том же D1 batch.
- Скриншот можно удалить в личном кабинете. API проверяет владельца и источник запроса, удаляет объект R2 и запись D1, очищает ссылки операций. Удаление счёта предлагает перенос операций или удаление вместе с ними; переводы, ставшие переводами на тот же счёт, удаляются. Цели можно изменить и удалить.
- «Личный кабинет → Управление данными → Удалить все мои данные» требует двух подтверждений, включая ввод `УДАЛИТЬ`. Удаляет бюджет, версии и изображения аккаунта, затем локальные данные. Сервер сохраняет только служебный номер поколения, блокирующий повторную загрузку старым устройством. Загрузка изображения, начатая до удаления, также не может вернуть его после удаления.
- Размер JSON после миграции допускается до 4 МиБ; ограничение ZIP согласовано с ним. Старый профиль ZIP версии 1.6 поддерживается.

## Автоматические проверки

Все команды прошли:

```sh
node scripts/test-data-lifecycle.mjs
node scripts/test-privacy-actions.mjs
node scripts/test-finance.mjs
node scripts/test-monthly-budget.mjs
node scripts/test-backups.mjs
node scripts/test-cloud.mjs
node scripts/test-pwa.mjs
npx tsc --noEmit
```

Новые тесты проверяют миграцию, стабильные ID, удаление на устройстве A при более поздней несвязанной правке на B, очистку спустя 90 дней, повторное добавление лимита, перенос и удаление счёта, изменение/удаление цели, предупреждение перед выходом, остановку выхода при неудачной синхронизации, очистку только данных владельца в localStorage и IndexedDB.

Сервер проверен в изолированных D1/R2: 100 последовательных сохранений создают один снимок; проверены периодические/принудительные снимки и правило 30 + 12 месяцев. Проверены удаление изображений, чужой владелец, неверный Origin, очистка ссылок, полное удаление, запрет старого сохранения с revision 0 и очистка загрузки, пересёкшейся с удалением. Реальные пользовательские данные в этих тестах не удалялись.

ZIP-тесты проверяют архив со старым schema-1 JSON, миграцию целей и сохранение пользовательских полей; также архив с JSON более 2 МБ. Ранее существовавшие проверки распознавания, выбора месяца, лимитов и восстановления продолжают проходить.

## Ручная проверка на Android и iPhone Safari

Браузерная проверка на реальном телефоне не выполнена; автоматические проверки выше её не заменяют. Следующие действия следует выполнять на тестовом аккаунте:

1. Открыть приложение и применить обновление до v1.8. Проверить месяцы, категории и лимиты.
2. Загрузить банковский скриншот, добавить операции, проверить счёт по последним четырём цифрам, даты и категории.
3. Изменить бюджет без сети, нажать «Выйти»: проверить три варианта. «Синхронизировать и выйти» без сети должен оставить данные и аккаунт. Скачать копию, убедиться, что файл сохранён; после подтверждённого выхода проверить повторный вход.
4. Создать два счёта и перевод между ними. Удалить один с переносом операций; проверить остатки и историю. На отдельном примере удалить счёт вместе с операциями.
5. Изменить цель и удалить её. Проверить анимации и отмену диалогов.
6. Удалить один исходный скриншот: операции остаются, изображение больше не открывается. Восстановить старый ZIP на тестовом аккаунте.
7. Открыть тестовый аккаунт на двух устройствах. Удалить операцию на A, изменить другую на B, объединить: удалённая операция не возвращается.
8. Скачать полную копию тестового аккаунта. Выполнить «Удалить все мои данные» с двойным подтверждением; переподключить старое устройство и проверить, что оно не возвращает данные. Затем начать новый бюджет.
