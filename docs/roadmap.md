Зафиксировано 16.10.2026. Платформа для ведения бюджета и продаж: «Финансы» («Личное» бесплатно, «Бизнес» по подписке), отдельная программа «Склад», общие интеграции с внешними сервисами. Безопасность — в [security-plan.md](security-plan.md).

## Тарифы (решено 16.10.2026)

| | **Личное** — бесплатно | **Бизнес** — ежемесячная подписка |
|---|---|---|
| Суть | Обычная версия «Финансов» без дополнительных возможностей | Полностью готовый продукт для бизнеса, всё включено |
| Учёт денег | Личный бюджет: ручной ввод, импорт скриншотов, категории, аналитика, синхронизация, бэкапы. Удобства ввода: автоввод из уведомлений банков на Android, импорт выписок файлом, Telegram-бот | Всё из «Личного» + бизнес-пространство: выручка, расходы, прибыль, налог |
| «Склад by ogma» | — | Входит полностью |
| Интеграции | — | Маркетплейсы, банки по API, ОФД, «Мой налог», 1С и другие |
| Команда | — | Сотрудники, роли и права |
| Десктоп-версия | — | Да |

Решено: удобства ввода для обычных людей (автоввод из уведомлений Android, импорт выписок файлом, Telegram-бот) входят в бесплатное «Личное» — они привлекают пользователей, а бизнес-функции остаются в подписке.

## 1. Основа для бизнеса и интеграций — новая модель данных

Без этого шага интеграции не сделать: сейчас бюджет хранится одним документом на пользователя.

- [ ] Операции — отдельными строками в базе, а не одним документом.
- [ ] **Пространства:** «Личное» и «Бизнес» у одного аккаунта, данные раздельно, общий вход.
- [ ] **Источник каждой записи:** вручную, скриншот, уведомление банка, маркетплейс, склад, банк по API. У записи из внешней системы — внешний идентификатор, чтобы повторная загрузка не создавала дубли.
- [ ] Типы записей: доход, расход, перевод, продажа, комиссия, возврат, выплата, списание товара.
- [ ] Контрагенты: покупатели, поставщики, маркетплейсы, банки.
- [ ] Перенос существующих данных пользователей без потерь.

## 3. Интеграции — слой коннекторов

### Как устроен коннектор (общая схема для всех)

1. Пользователь подключает сервис: вводит API-ключ или входит через OAuth.
2. Ключ хранится на сервере зашифрованным, отдельно от данных.
3. Сервер по расписанию (и по webhook, где есть) забирает новые данные.
4. Данные приводятся к единым записям платформы (раздел 1) с источником и внешним ID.
5. Журнал синхронизации: когда, сколько загружено, ошибки; кнопки «обновить сейчас» и «отключить».
6. Только права на чтение там, где это возможно.

### Очередь интеграций

| Приоритет | Интеграция | Что даёт | Пространство |
|---|---|---|---|
| 1 | **Склад ↔ Финансы** (своя программа «Склад», раздел 4) | Продажа и списание со склада сразу видны в деньгах и прибыли | Бизнес |
| 2 | **Ozon** (Seller API) | Заказы, продажи, комиссии, возвраты, выплаты, остатки | Бизнес |
| 2 | **Wildberries** (API продавца) | То же для WB | Бизнес |
| 3 | **Яндекс Маркет** (Partner API) | То же для Маркета | Бизнес |
| 3 | **Android: уведомления банков** | Автоввод операций из push-уведомлений без скриншотов | Личное и бизнес |
| 4 | **Банковские выписки файлом** (1С, CSV, OFX) | Импорт истории за любой период | Личное и бизнес |
| 4 | **Банки по API для бизнеса** (Т-Банк, Точка, Сбер Бизнес и др.) | Операции по расчётному счёту автоматически | Бизнес |
| 5 | **«Мой налог» / НПД** | Учёт чеков и налога самозанятого (через партнёрский доступ ФНС, нужен договор) | Бизнес |
| 5 | **ОФД / онлайн-кассы** | Чеки продаж из кассы | Бизнес |
| 5 | **Экспорт в 1С и бухгалтерию** | Передача данных бухгалтеру | Бизнес |
| — | **Telegram-бот** | Уведомления, быстрый ввод расходов | Личное и бизнес |

Порядок можно менять под реальных пользователей: сначала тот маркетплейс, на котором работают первые бизнес-клиенты.

### Безопасность интеграций

- [ ] API-ключи и токены пользователей — шифрование отдельным ключом, не в открытом виде в базе и журналах.
- [ ] Минимальные права: только чтение, где сервис это позволяет.
- [ ] Проверка подписи входящих webhook.
- [ ] При отключении интеграции или удалении аккаунта — удаление токенов и отзыв доступа.
- [ ] Персональные данные покупателей из заказов маркетплейсов (ФИО, адреса, телефоны) не храним, если они не нужны для учёта.
- [ ] Ограничение частоты запросов к внешним API, повтор при сбоях, оповещение при постоянных ошибках.

## 4. «Склад by ogma» — отдельная программа

Самостоятельное приложение для учёта товара. Входит в подписку «Бизнес», отдельно не продаётся. Вместе с «Финансами» работает как одна система.

### Как связано с «Финансами»

- **Один аккаунт ogma:** вход один раз, общий сервер и общая база пользователей. Приложения разные: свой интерфейс и свой адрес, например `sklad.ogma.ru` и `app.ogma.ru`.
- **Склад отвечает за товар:** что, сколько, где лежит, по какой себестоимости.
- **Финансы отвечают за деньги:** выручка, расходы, прибыль, налог.
- **Синхронизация:** продажа, закупка, возврат или списание на складе автоматически создаёт запись в бизнес-пространстве «Финансов» с источником «Склад» и ссылкой на документ. Повторов нет, отмена документа отменяет запись.
- **Маркетплейсы подключаются один раз к платформе ogma.** Склад берёт оттуда заказы и остатки, Финансы — комиссии, выплаты и возвраты.
